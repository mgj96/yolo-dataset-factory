# 데이터셋 쌓는 순서 (연구자·학자용 워크플로)

YOLO 학습용 데이터셋을 수집·라벨링·검수까지 한 흐름으로 구성하는 방법과 용어를 정리합니다.

---

## 1. 개요

| 항목 | 설명 |
|------|------|
| **목적** | 이미지 업로드 → 분석(설정 자동 채움) → 라벨링·검수 → 정제된 데이터로 저장 → YOLO 형식 데이터셋 산출. |
| **워크플로** | 업로드를 진입점으로 두고, 업로드 직후 세션 생성·분석으로 데이터셋·라벨링 설정을 자동 채운 뒤, 검수 완료 시에만 정제된 데이터로 판별·학습에 사용. |
| **적합성 조절** | confidence 임계값(conf_threshold)으로 검출 결과를 얼마나 엄격하게 걸러 쓸지 조절. |
| **정제된 데이터** | "검수 완료"한 이미지/라벨만 정제된 것으로 간주. 학습 시 정제된 데이터만 사용할 수 있음(옵션). |

---

## 2. 단계별 워크플로

### 1단계: 이미지 업로드

- **이미지를 먼저 업로드**합니다. 업로드 시 **새 세션**이 생성되며, 해당 세션 ID로 이미지가 저장됩니다.
- 기존 데이터셋에 이어서 넣으려면 데이터셋을 선택한 뒤 이미지 목록을 불러온 다음 업로드하면 해당 데이터셋에 추가됩니다.
- API: `POST /api/dataset/frames` (dataset_id 생략 또는 `session=true` 시 세션 생성), `GET /api/dataset/{id}/images` (목록 조회).

### 2단계: 분석 및 설정

- 업로드된 이미지에 대해 **분석 실행**을 누르면, 서버가 후보 클래스로 1회 추론하여 **검출된 클래스만 제안**하고, 초기 라벨·메타를 저장합니다.
- 제안된 **클래스명·적합성(confidence 임계값)**은 UI에서 수정 가능합니다. 수정한 뒤 **자동 라벨 실행**으로 다시 생성할 수 있습니다.
- API: `POST /api/dataset/{id}/analyze` (후보 클래스·conf_threshold; 응답에 suggested_class_names, 초기 라벨 저장), `POST /api/dataset/{id}/auto-label` (클래스·임계값 지정 후 재실행).

### 3단계: 적합성 조절

- 분석/자동 라벨 결과(bbox 개수, 객체 있는 이미지 수)를 확인합니다.
- 검출이 너무 많거나 적으면 **conf_threshold**를 바꾼 뒤 분석 또는 자동 라벨을 다시 실행합니다.

### 4단계: 라벨링 및 검수

- 이미지 목록에서 **미검수 / 검수완료** 상태를 확인합니다.
- 이미지별 "편집"으로 들어가 bbox를 수정·삭제·추가한 뒤:
  - **저장**: 라벨(.txt)만 저장.
  - **저장 및 검수 완료**: 라벨 저장 후 해당 이미지를 "검수완료"로 표시. 이 시점부터 **정제된 데이터**로 판별됩니다.
- UI에서 «정제된 데이터만 보기»로 검수 완료된 이미지만 필터링할 수 있습니다.
- API: `GET /api/dataset/{id}/labels` (쿼리 `refined_only=true` 시 검수 완료 stem만), `GET/PUT /api/dataset/{id}/labels/{stem}`, `GET/PUT /api/dataset/{id}/labels/{stem}/meta`.

### 5단계: 내보내기·학습

- 데이터셋 루트의 `data.yaml`과 `images/`, `labels/` 디렉터리를 학습 파이프라인에 투입합니다.
- **검수 완료한 정제된 데이터만** 학습에 쓰려면 라벨링 화면에서 «정제된 데이터만 보기»로 확인한 뒤, 해당 이미지/라벨만 사용하거나, API `GET /api/dataset/{id}/info?refined_only=true` 의 `refined_stems` 등을 참고해 필터링할 수 있습니다.
- 학습 진입점(CLI 예시·경로)은 앱의 데이터셋 정보 또는 라벨링 화면에서 확인할 수 있습니다.

---

## 3. 용어 정리

| 용어 | 설명 |
|------|------|
| **세션** | 업로드 시 생성되는 임시 작업 단위. 세션 ID는 dataset_id와 동일한 저장 구조(images/, labels/)를 사용. |
| **분석** | 업로드된 이미지에 대한 1회 YOLO-World 추론. 검출된 클래스·설정 제안 및 초기 라벨 자동 저장. |
| **적합성 조절** | confidence threshold(임계값)로 검출 품질·개수를 조절하는 것. |
| **검수** | 자동 생성된 라벨을 사람이 확인하고 수정·보완한 뒤 "검수 완료"로 표시하는 단계. |
| **정제된 데이터** | 검수 완료(reviewed / manual_labeled)된 이미지·라벨. 학습용으로 사용 권장. |
| **메타데이터** | 검수 상태(status), confidence, source 등을 담은 `labels/*.json`. |

---

## 4. 요약

1. **이미지 업로드** (새 세션 또는 기존 데이터셋) → 2. **분석 실행**(설정 자동 채움) 또는 **자동 라벨** → 3. **필요 시 적합성 재조절** → 4. **라벨링·검수(편집 + 검수 완료)** → 5. **정제된 데이터 확인** → 6. **data.yaml·images·labels로 학습**.

이 순서를 지키면 업로드부터 정제까지의 "박자(진행률)"를 유지하면서 품질을 관리할 수 있습니다.
