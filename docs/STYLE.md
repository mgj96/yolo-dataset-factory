# 스타일 가이드

## 1. 문서 스타일

- **언어**: 기본 한국어, 기술 용어는 영문 유지(예: API, endpoint, inference).
- **구조**: 제목 레벨 1(문서 제목) → 2(대섹션) → 3(소섹션). 개요 → 상세 → 요약 순 권장.
- **표**: 헤더 행 명시, 셀 정렬 일관. 마크다운 파이프 `|` 사용.
- **코드 인용**: 인라인은 백틱, 블록은 언어 지정(예: `python`, `bash`).

## 2. 코드 스타일

- **네이밍**: 함수·변수 snake_case, 클래스 PascalCase, 상수 UPPER_SNAKE_CASE.
- **주석**: 한글 또는 영문 일관. 복잡한 로직·비즈니스 판단에만 상세 주석.
- **예외**: 예외 처리 시 로그 또는 재발생 명시; 빈 except 지양.
- **타입**: 함수 시그니처에 타입 힌트 사용 권장(Python 3.x).

## 3. 용어집

| 용어 | 설명 |
|------|------|
| 엔드포인트 | API 경로(예: `/upload`) |
| 추론 | YOLO 모델의 predict/forward |
| 전처리 | letterbox 등 입력 이미지 변환 |
| 감리 | 소스 품질·규칙·보안 점검 |
| 재지시 | 감리 결과를 바탕으로 후속 작업 목록 출력 |
| 적합성 조절 | confidence threshold(임계값)로 검출 품질·개수 조절 |
| 라벨링 처리 | 자동 라벨 생성 + 검수(수정·보완)까지의 흐름. 자세한 단계는 docs/DATASET_WORKFLOW.md 참고 |
